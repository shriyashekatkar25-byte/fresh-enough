01 · the decision

What should the default sync cadence be?

problem

[ˈprä-bləm] noun

A marketing ops lead connects survey responses to a churn dashboard and expects it to be "live." The source app meters API calls per day. Sync too often and the connector eats the customer's quota and their other tools start failing; sync too rarely and the dashboard tells yesterday's story at this morning's standup.

Customer problem

change

[ˈchānj] noun

Pick one default schedule for newly created SaaS connector pipelines: every 15 min, 1 hour, 6 hours or 24 hours. Users can still override it; most never do, so the default is the product.

Proposed change

north star

[ˈnȯrth ˈstär] noun

Fresh-and-safe day rate: the share of customer-days where a dashboard read sees data within the freshness target and the connector stayed inside the source API's daily quota.

Success metric

guardrails

[ˈgärd-ˌrālz] plural noun

  • Quota-breach days ≤ 2%
  • P90 staleness at read ≤ the freshness target
  • Median quota used ≤ 60% (leave room for the customer's other tools)
  • Sync compute ≤ $40 per connector-month

Who cares

dart

[ˈdärt] noun, Monte Carlo sense

One simulated customer-day. Its x is staleness ÷ target, its y is API calls ÷ quota. If it lands in the unit square, the day was fresh and safe. Count the darts inside.

04 · the math, from my Monte Carlo course

Counting darts is estimating an area

fraction inside

[Ch1] estimator

Every customer-day is a random point. The probability we care about is the "area" of the safe square, weighted by how likely each point is. Throw n points and count k inside: p̂ = k/n.

k ~ Binomial(n, p)  ⇒  E[p̂] = p
Var(p̂) = p(1−p)/n

So p̂ is unbiased, and its variance falls like 1/n: four times the darts halves the error bar. That is the band you see tightening on the trace.

sample mean

[Ch1] expectation

Cost per connector-month is an expectation: E[cost] ≈ (1/n)·Σ costᵢ. The Strong Law of Large Numbers says this average settles on the true value as n grows, with probability one.

E[staleness] = ∫₀ᶜ (t/c)… dt
= width × average height ≈ c/2 + sync time

A read lands uniformly inside a sync window of width c, so the average age is about half the cadence plus how long the sync takes. The simulation checks that by brute force and adds the messy parts (failures, retries, heavy-tailed volume) that the clean formula can't.

seeded RNG

[Ch1] reproducibility

The page uses a seeded pseudorandom generator, so seed 102 always gives the same 6,000 days. A PM can paste a seed into a review doc and everyone sees the same board. Change the seed to see how much of the answer is noise.

same seed → same darts → same memo

05 · how I'd run it on real data

From darts to tables

Replace simulated days with observed ones: one row per pipeline per day, joined to how many API calls it used and how old the data was when a dashboard actually read it. Table names below are illustrative.

-- 1. one row per connector-day: was it fresh AND safe?
WITH days AS (
  SELECT r.pipeline_id, r.day, r.sync_cadence_min,
         u.api_calls / u.daily_quota          AS quota_ratio,
         r.p50_read_staleness_min / t.target_min AS stale_ratio
  FROM apm_lab.ingest_ops.connector_read_freshness r
  JOIN apm_lab.ingest_ops.source_api_usage u USING (pipeline_id, day)
  JOIN apm_lab.ingest_ops.freshness_targets t USING (pipeline_id)
  WHERE r.source IN ('surveymonkey','eloqua','asana')
)
SELECT sync_cadence_min,
       COUNT(*) AS n_days,
       AVG(CASE WHEN stale_ratio <= 1 AND quota_ratio <= 1
                THEN 1.0 ELSE 0 END) AS fresh_safe_rate,
       AVG(CASE WHEN quota_ratio > 1 THEN 1.0 ELSE 0 END) AS breach_rate,
       PERCENTILE(quota_ratio, 0.5) AS median_quota
FROM days GROUP BY sync_cadence_min;
# 2. fit the simulator's inputs from real days, then throw darts
import numpy as np
df = spark.table("apm_lab.ingest_ops.connector_daily").toPandas()
rng = np.random.default_rng(102)

# bootstrap real customer-days instead of assuming a shape
idx  = rng.integers(0, len(df), size=20_000)
objs = df.objects.values[idx]
vol  = df.records.values[idx]

def fresh_safe(cadence_h, target_h, quota):
    syncs = 24 / cadence_h
    calls = syncs * (1 + objs + np.ceil(vol / syncs / 100))
    stale = rng.uniform(0, cadence_h, len(idx)) + df.sync_h.values[idx]
    inside = (stale <= target_h) & (calls <= quota)
    p = inside.mean()
    se = np.sqrt(p * (1 - p) / len(idx))   # Ch1: Binomial SE
    return p, se

for c in (0.25, 1, 6, 24):
    print(c, fresh_safe(c, target_h=2, quota=2500))
